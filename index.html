Why Glyx

Everything you check every day,
in one calm place.

Stop opening five tabs every morning. Glyx keeps it all on your desktop, and stays light enough that you forget it is running.

Accounts or trackers

One config file

Your whole dashboard is glyx.yml. Save it and Glyx reloads only the widgets that changed. A typo never wipes your setup.

Sandboxed plugins

Every widget runs in its own iframe and can only reach the hosts it declares. The Rust host checks every call.

Local-first

No server, no telemetry, no sign-in. Your data, including your AI usage, never leaves your machine.

Configuration

Edit a file.
Watch it update.

Pages, columns and widgets, all in plain YAML. Back it up, diff it, keep it in your dotfiles or share it with a friend.

  • Hot reload in under a second, no restart
  • Safe errors: keeps the last good config and points to the line
  • Themes in dark, light or system, with your own accent
%APPDATA%\Glyx\glyx.ymlReloaded
theme:
  preset: dark
  accent: "#7aa2f7"

window:
  mode: widget       # normal | widget | tray

pages:
  - name: Home
    columns:
      - size: small
        widgets:
          - plugin: glyx.clock
          - plugin: glyx.weather
            config: { location: Hanoi }
      - size: full
        widgets:
          - plugin: glyx.rss
            refresh: 15m
            config:
              feeds:
                - https://hnrss.org/frontpage
my.stars/main.js
// No build step. Just HTML and JS.
host.onRefresh(async () => {
  const { repo } = await host.config();
  const data = await host.fetchJson(
    `https://api.github.com/repos/${repo}`
  );
  stars.textContent = `★ ${data.stargazers_count}`;
});

Plugins

Every widget is a plugin.
Write yours in minutes.

A plugin is a folder with a manifest and a web page. The SDK gives you fetch with caching, storage, system stats and theme colors.

  • Declared permissions: a plugin can only call the hosts it lists
  • No direct network: raw fetch and WebSocket are blocked
  • Typed SDK with TypeScript definitions
